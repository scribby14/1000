# Инцидент 24.08.2026: Claude Code упал во время установки Касперского

## Что случилось

Ближе к завершению установки Kaspersky снова умер GPU-процесс Claude Code —
та самая сессия, что разбиралась с криптопроблемой. Снимок
`check-gpu-health.ps1` на вечер 24.08:

| Время (24.08, если не указано) | exitCode | Классификация |
| --- | --- | --- |
| 21.08 19:32:24 | 34 | benign — сброс GPU при установке драйвера |
| 14:52:08 | 101457950 | REAL CRASH |
| 15:14:20 | 101457950 | REAL CRASH |
| 15:57:33 | 34 | benign — сброс GPU при установке драйвера |
| 16:05:37 | 101457950 | REAL CRASH |
| 16:45:03 | 101457950 | REAL CRASH |
| 18:06:19 | 101457950 | REAL CRASH — **совпало с финалом установки Kaspersky** |

Активный драйвер: Intel 32.0.101.7088 (INF от 17.06.2026).
В DriverStore лежит и старый пакет 32.0.101.5972 (19.08.2024).
`Windows Update driver search = 1` — WU может доставлять драйверы.

Код 101457950 = 0x060C201E — нестандартный код завершения (не код результата
Chromium и не NTSTATUS): процесс умирает аварийно, а не завершается сам.

## Выводы из снимка

1. **Откат драйвера так и не выполнен.** Активен по-прежнему 7088, «хороший»
   5972 лежит в хранилище без дела. Не исключено, что откат делался, а WU
   вернул 7088 обратно (событие 15:57 — чья-то установка драйвера, после неё
   падения продолжились уже через 8 минут).
2. **WU не заблокирован** (search = 1): пока это так, любой откат живёт до
   первой проверки обновлений.
3. **Падение 18:06 при установке Kaspersky — скорее всего не совпадение.**
   На финальной стадии установки Kaspersky запускает службы и драйвер
   `klhk.sys`, который внедряет user-mode-перехватчики во **все уже запущенные
   процессы**. Внедрение чужой DLL в песочницу GPU-процесса Chromium/Electron —
   классическая причина его мгновенной смерти. Проверяется скриптом
   `scripts/check-av-injection.ps1`: если в процессах Claude видны `kl*`-DLL —
   гипотеза подтверждена.
4. **Но Касперский — не первопричина серии.** Четыре таких же падения
   (14:52–16:45) произошли до его установки. Основной подозреваемый —
   по-прежнему драйвер 7088. Теперь факторов риска два, и устранять нужно оба,
   иначе после отката драйвера падения могут продолжиться уже из-за хуков
   антивируса, и картина смажется.

## Побочный эффект Касперского: TLS (та самая «крипто»-тема)

Если в Kaspersky включена «Проверка защищённых соединений», он подменяет
сертификаты HTTPS своим. Node/Claude Code начнёт видеть в цепочке сертификат
Kaspersky и может сыпать ошибками вида `SELF_SIGNED_CERT_IN_CHAIN` /
`unable to get local issuer certificate`. Проверка — блок «TLS» в
`check-av-injection.ps1`. Если криптопроблема, которую разбирала упавшая
сессия, была про TLS/сертификаты — после установки Касперского главный
подозреваемый теперь он.

## План действий (по порядку)

1. **Исключить Claude из Касперского** — инструкция в
   `docs/kaspersky-exclusions.md`.
2. **Убедиться, что инжект прекратился**: перезапустить Claude Code и выполнить
   `check-av-injection.ps1`.
3. **Откатить драйвер и заблокировать WU**: `fix-intel-driver.ps1`
   (PowerShell от администратора; Claude Code закрыть — экран мигнёт).
4. **Перезагрузиться** и запустить `check-gpu-health.ps1`. Ожидаем:
   `DriverVersion = 32.0.101.5972`, `Windows Update driver search = 0`.
   Одно событие exitCode 34 вокруг отката — норма.
5. **Понаблюдать день работы.** Критерий успеха: ни одного 101457950.
6. **Если падения продолжатся** — план Б: запускать Claude с ключом
   `--disable-gpu` (программный рендеринг; для Claude Code это ничем не
   мешает) и включить сбор дампов (WER LocalDumps) для точной атрибуции.
   Это следующая итерация — сначала пункты 1–5.

## Упавшая сессия не потеряна

Разговор восстанавливается: в терминале — `claude --resume` (выбрать сессию из
списка) или `claude --continue` (продолжить последнюю); в настольном
приложении — через историю чатов.
