# Исключение Claude Code из контроля Касперского

Цель — чтобы Kaspersky:
1) не внедрял перехватчики в процессы Claude (они роняют GPU-процесс);
2) не подменял TLS-сертификаты (ошибки соединения у node/Claude Code).

## 1. Узнать точный путь к exe

При запущенном Claude, в PowerShell:

```powershell
Get-Process claude* | Select-Object -ExpandProperty Path -Unique
```

Команда выведет **два** exe — это разные программы:

- `C:\Program Files\WindowsApps\Claude_<версия>_...\app\Claude.exe` —
  настольное приложение (Electron). **Его GPU-процесс и падает — добавлять
  в доверенные нужно в первую очередь его.**
- `C:\Users\<user>\AppData\Roaming\Claude\claude-code\<версия>\claude.exe` —
  движок Claude Code (CLI), который настольное приложение запускает как
  дочерний процесс. Отдельная запись для него не обязательна: галочка
  «Не контролировать активность дочерних программ» у настольного Claude.exe
  покрывает его автоматически.

  **Для приложения из Microsoft Store этот путь — виртуальный (MSIX).**
  Снаружи пакета его не существует: Проводник не покажет папку
  `Roaming\Claude`, а Касперский на такой путь скажет «Указанный путь не
  существует». Реальные файлы лежат в
  `%LOCALAPPDATA%\Packages\Claude_<хеш>\LocalCache\Roaming\Claude\claude-code\…`.
  Ещё одна причина не заводить для движка отдельную запись, а положиться на
  галочку про дочерние программы у настольного Claude.exe.

Положить путь настольного приложения в буфер обмена одной командой
(Claude должен быть запущен), дальше просто Ctrl+V в поле Касперского:

```powershell
(Get-Process claude* | Where-Object { $_.Path -like '*WindowsApps*' } |
  Select-Object -First 1 -ExpandProperty Path) | Set-Clipboard
```

**Осторожно: пути версионные.** И `WindowsApps\Claude_<версия>`, и
`claude-code\<версия>` меняются при обновлениях — путь, записанный час назад,
может уже не существовать (Касперский скажет «Указанный путь не существует»).
Всегда берите путь свежей командой при запущенном Claude и не тащите хвостовой
пробел при копировании из терминала. Если после очередного обновления Claude
падения вернутся — первым делом проверьте, что записи в доверенных всё ещё
указывают на существующие файлы.

## 2. Добавить в доверенные программы

Kaspersky (Standard / Plus / Premium, 2025–2026): шестерёнка (Настройки) →
**Угрозы и исключения** → **Указать доверенные программы** → **Добавить** →
выбрать exe из шага 1 и отметить:

- **«Не контролировать активность программы»** — главное: убирает внедрение
  хуков в процессы;
- **«Не контролировать активность дочерних программ»** — покрывает GPU-процесс
  и node.exe, которые Claude порождает;
- **«Не проверять весь трафик»** (или минимум «Не проверять шифрованный
  трафик») — убирает подмену TLS-сертификатов.

Названия пунктов слегка отличаются между версиями и языками продукта.

Два практических момента про интерфейс:

- Нужен именно раздел **«Указать доверенные программы»**: после добавления exe
  открывается карточка с галочками «Не контролировать активность…». Если
  галочек нет — вы в соседнем разделе «Настроить исключения» (исключение из
  проверки файлов); он от внедрения хуков не защищает.
- В диалоге выбора файла дерево папок может не показывать `AppData` (скрытая)
  и `WindowsApps` (системная) — это нормально: вставьте полный путь текстом в
  нижнее поле и нажмите «Выбрать».

## 3. Перезапустить Claude Code и проверить

```powershell
powershell -ExecutionPolicy Bypass -File .\check-av-injection.ps1
```

Ожидаем: у всех процессов Claude — `no Kaspersky modules loaded`.

Что именно это доказывает: на Kaspersky 21.x (версия на `scrib`) эта строка
появляется и без всяких исключений — продукт не внедряет DLL в пользовательские
процессы, а работает через драйверы ядра (установлено 25.08.2026). То есть вывод
подтверждает «инжекта нет», но не подтверждает «исключение применилось». Что
исключение действительно работает, показывает только отсутствие падений
GPU-процесса (exitCode 101457950) за день работы.

Про блок TLS: тест выполняется из PowerShell, а не из процесса Claude, поэтому
галка «Не проверять весь трафик» у Claude на его результат не влияет —
`TLS IS INTERCEPTED` после настройки не означает, что исключение не работает.
`TLS is NOT intercepted` появится, только если проверка защищённых соединений
отключена глобально или домен добавлен в доверенные адреса. Реальный критерий
для Claude — отсутствие ошибок сертификатов в самом Claude Code.

## Альтернатива только для TLS

Если проверку трафика хочется оставить, а node ругается на сертификаты:

- Настройки → **Сеть** → «Проверка защищённых соединений» → добавить
  `api.anthropic.com` и `claude.ai` в доверенные адреса; **или**
- экспортировать корневой сертификат Kaspersky и указать его в переменной
  окружения `NODE_EXTRA_CA_CERTS` для Claude Code.

Достаточно одного из вариантов.
